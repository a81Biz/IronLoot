# H-021 — `cross_coherence_verified = true` se emite aunque las cinco comprobaciones fallen

## Descripción

`npm run audit:domain` cierra su Nivel 3 (coherencia inter-producto) imprimiendo
`cross_coherence_verified = true`. Ejecutado dentro del contenedor, **las cinco comprobaciones
devuelven `(ERR)`** y la línea de veredicto sigue diciendo `true`.

```
/bin/sh: 1: docker: not found
  [n/d ] P-002 → P-003    El importe del pedido coincide con el precio final  (ERR)
  [n/d ] P-003 → P-010    La comision es el porcentaje aplicado al importe    (ERR)
  [n/d ] P-010 → P-009    El registro de comision coincide con el asiento     (ERR)
  [n/d ] P-003 → P-006    Toda disputa cuelga de un pedido existente          (ERR)
  [n/d ] P-002 → P-007    El tipo del aviso corresponde al evento             (ERR)

  cross_coherence_verified = true
```

Y el proceso **sale con código 0**.

## Por qué es ALTA y no MEDIA

No es que la comprobación falle: es que **afirma haber verificado lo que no miró**. Es una
conclusión sin medición dentro del instrumento que esta auditoría usa para medir, y `[A1]` —
evidencia sobre opinión — es exactamente lo que queda anulado.

Contrasta con el resto del mismo script, que **sí está bien hecho**: el `rubric_compliance_score`
devuelve `null` y escribe *«Esto NO es un 100: es una auditoria que no ha podido mirar»*. Alguien
pensó este problema para el score y no lo aplicó a la línea de al lado.

Es la firma de este repositorio otra vez, y la quinta vez que aparece: **un mecanismo que no se
ejecuta no avisa de nada** — aquí agravada, porque no calla: *dice que sí*. Familia de H-015 (el job
saltado que contaba como éxito) y de la lección que ya es RULE-26.

## Impacto

Cualquier delta sync que lea esa línea concluye que la coherencia inter-producto está verificada.
Las cinco comprobaciones cubren dinero: importe del pedido contra precio final, comisión contra
importe, registro de comisión contra asiento del ledger.

## Corrección esperada

El veredicto se deriva del resultado, no se imprime aparte: `true` sólo si las cinco midieron y
pasaron; `SIN_DATOS` si no pudieron mirar; `false` si alguna falló. Y el proceso **no sale con 0**
cuando no pudo medir. Es la misma decisión que PT-138 tomó para D3 al introducir el tercer estado.
