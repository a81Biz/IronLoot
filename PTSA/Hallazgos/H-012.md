# H-012 — El aviso al vendedor reutiliza el tipo del comprador

## Descripcion

Al cerrar una subasta se emiten dos notificaciones con el **mismo tipo** y significados distintos:

| Tipo | Destinatario | Mensaje |
|---|---|---|
| `AUCTION_WON` | comprador | «Congratulations! You have won…» |
| `AUCTION_WON` | **vendedor** | «Your auction … sold» |

El catalogo no tiene `AUCTION_SOLD`, y el codigo lo declara:

```ts
NotificationType.AUCTION_WON, // Reuse type or add AUCTION_SOLD if exists, for now WON implies completion
```

## Impacto

**Ninguno visible hoy.** El texto del mensaje distingue los dos casos, asi que quien lea la lista no
se confunde.

Lo que falla es el **tipo como discriminador**: un consumidor que filtre `AUCTION_WON` para mostrar
«mis subastas ganadas» le enseñaria al vendedor su propia venta como una victoria. Hoy no existe ese
filtro; el dia que exista, el defecto aparece ya introducido.

## Por que se registra pese a estar declarado en un comentario

P-007 se fija a si mismo el invariante **«tipo de notificacion correcto para el evento»** (F3). Dos
eventos distintos compartiendo tipo no cumplen ese invariante.

Que el atajo este comentado lo hace **honesto, no correcto**. Y es lo unico que impide que P-007
llegue a `VALIDADO`.

## Por que BAJA

`[R40]`: «defecto menor, cosmetico o de bajo impacto». No hay dinero, ni datos, ni funcionamiento
comprometido. Pero probabilidad 4: ocurre en **cada** cierre de subasta.

## Recomendacion

Añadir `AUCTION_SOLD` al enum y usarlo en `auction-scheduler.service.ts:204`. Es una migracion
aditiva de enum y un cambio de una linea.

## Estado

`ABIERTA`. **El agente no cierra hallazgos de dominio.**
