# H-023 — El catálogo OpenAPI publica dos esquemas distintos bajo el nombre `UserResponseDto`

## Descripción

En **cada arranque** del API, los logs traen:

```
level: warn — Duplicate DTO detected: "UserResponseDto" is defined multiple times
with different schemas. Consider using unique class names or applying
@ApiExtraModels() decorator with custom schema names.
Note: This will throw an error in the next major version.
```

`/docs` publica el contrato del API. Dos formas distintas bajo un solo nombre significan que quien
lea el catálogo **no sabe cuál de las dos recibirá**.

## Por qué D4 y no D2

El código funciona; lo que está mal es lo que el sistema **dice de sí mismo**. El catálogo es
documentación generada, y una documentación ambigua es fidelidad documental, no integridad
arquitectónica.

## La fecha de caducidad

*«This will throw an error in the next major version»*. El día que alguien suba de mayor la librería
de Swagger, **el arranque deja de completarse** — y el aviso llevará meses en los logs de cada
arranque sin que nadie lo haya recogido. Ése es todo el motivo de registrarlo: es pequeño hoy y no lo
será el día que se convierta en error, y para entonces será «se rompió al actualizar» en vez de «lo
sabíamos».

## Corrección esperada

Renombrar uno de los dos, o `@ApiExtraModels()` con nombre de esquema explícito.
