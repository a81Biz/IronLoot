# E-015 — El aviso al vendedor reutiliza el tipo del comprador

## Contenido capturado

Notificaciones reales tras cerrar una subasta:

```
BID_OUTBID   | A higher bid of $700 has been placed...  | comprador_152121
BID_OUTBID   | A higher bid of $950 has been placed...  | comprador2_152121
AUCTION_WON  | Congratulations! You have won "Reloj..."  | comprador_152121   <- comprador
AUCTION_WON  | Your auction "Reloj de coleccion..."      | vendedor_152121    <- VENDEDOR
```

El catalogo de tipos:

```
AUCTION_WON  AUCTION_LOST  BID_OUTBID  ORDER_PAID  ORDER_SHIPPED  DISPUTE_UPDATE  SYSTEM
```

**No existe `AUCTION_SOLD`.** Y el codigo lo dice:

```ts
// auction-scheduler.service.ts:204
NotificationType.AUCTION_WON, // Reuse type or add AUCTION_SOLD if exists, for now WON implies completion
```

## Observacion

El mismo tipo carga **dos significados distintos** segun quien lo reciba: para el comprador «has
ganado», para el vendedor «tu subasta se vendio».

Es un atajo **declarado** —el comentario lo nombra— y el texto del mensaje si distingue los dos
casos, asi que una persona que lea la lista no se confunde.

Lo que si falla es el **tipo como discriminador**: cualquier consumidor que filtre por
`AUCTION_WON` para mostrar «mis subastas ganadas» le enseñaria al vendedor su propia venta como una
victoria.

## Por que se registra pese a estar declarado

P-007 se fija a si mismo el invariante **«tipo de notificacion correcto para el evento»**. Con dos
eventos distintos compartiendo tipo, ese invariante no se cumple — y es lo que impide que P-007
llegue a `VALIDADO`, no un fallo de funcionamiento.

Que el atajo este comentado lo hace honesto, no correcto.
