## D2 — `audit:schema` (deriva del esquema)

**Primera ejecución: FALLA.**

```
Error: P1003
Database `ironloot_db_shadow_check` does not exist on the database server at `db:5432`.
[audit:schema] FALLA — No se pudo comprobar la deriva del esquema (codigo 1).
               Un error de ejecucion no es un aprobado.
```

**El instrumento se comporta bien**: no dice OK, nombra la causa y **sale con 1**. Es la disciplina que
PT-149 impuso al veredicto de coherencia, aplicada aquí desde antes.

**No es un hallazgo**, y conviene decir por qué: `prisma migrate diff --from-migrations` **exige que la
base sombra ya exista** —lo descubrió PT-136 ejecutando, después de que un comentario afirmara lo
contrario— y el job `schema-drift` de CI **la crea explícitamente**. El checkpoint funciona donde está
declarado. Lo que falta es la base sombra en el entorno local, que nadie crea.

Creada a mano (`CREATE DATABASE ironloot_db_shadow_check`), el veredicto real:

```
[audit:schema] OK — las migraciones reproducen `schema.prisma`.
```

**Es la garantía que H-014 dejó**: el esquema se aplica por migración y las migraciones reproducen el
modelo. Verificado, no supuesto.

```
  [OK  ] P-002 → P-003    El importe del pedido coincide con el precio final  (0)
  [OK  ] P-003 → P-010    La comision es el porcentaje aplicado al importe  (0)

  5 de 5 medidas · 0 incoherente(s) · 0 sin poder mirar
```

**Y la base tiene CERO pedidos, cero pagos, cero comisiones y cero asientos** (`E-030`).

Las cinco consultas se ejecutaron sin error y devolvieron «0 incoherencias» **porque no había ninguna
fila que comparar**. El veredicto no distingue *«comparé y cuadra»* de *«no había nada que comparar»*.

Contraste con el resto del mismo fichero, que es lo que lo convierte en hallazgo y no en limitación:
`rubric_compliance_score` **sí** declara su denominador y saca las reglas sin datos. Y el propio
docstring de `veredictoCoherencia()` declara la protección que el código no implementa:

> *«Un catalogo vacio da `sin_datos`, no `verificado`: afirmar que se verifico la coherencia de cero
> pares es la version degenerada del mismo error.»*

`domain-rules.ts:383` sólo trata como `sin_datos` el caso `medidas === 0` —todas en `ERR`—; una consulta
que corre sobre cero filas cuenta como **medida**. → **H-025**
