# E-018 — El job «Integration Tests» no puede pasar, y bloquea `build` y `docker`

## Lo que declara el fichero

`.github/workflows/ci.yml:104-152`

```yaml
  test-integration:
    name: Integration Tests
    needs: lint
    services:
      postgres: { image: postgres:16-alpine, env: { POSTGRES_DB: ironloot_test } }
    steps:
      - Install dependencies:  npm install
      - Run E2E tests:         npm run test:e2e -- --passWithNoTests
        env: DATABASE_URL: postgresql://…/ironloot_test
```

Entre levantar Postgres y correr la suite **no hay ningún paso que cree el esquema**: ni
`prisma migrate deploy`, ni `prisma db push`, ni `prisma generate`. La base llega vacía.

Hay 17 ficheros en `src/api/test/e2e/`, así que `--passWithNoTests` no salva el job: hay tests que
correr.

## Reproducción 1 — contra base sin esquema (lo que hace CI)

```
$ CREATE DATABASE ptsa_ci;                      # vacía, sin esquema
$ DATABASE_URL=…/ptsa_ci NODE_ENV=test npx jest --config ./test/jest-e2e.json --passWithNoTests
```

Resultado: **el proceso no terminó**. Se dejó correr más de 10 minutos sin salida y la ejecución
completa acabó matada por consumo de memoria (`exit 137`).

## Reproducción 2 — contra base CON esquema, para aislar la causa

```
$ CREATE DATABASE ptsa_e2e; prisma db push          # esquema completo
$ DATABASE_URL=…/ptsa_e2e npx jest --config ./test/jest-e2e.json --runInBand --forceExit \
      --testPathPattern=auth

Test Suites: 2 passed, 2 total
Tests:       9 passed, 9 total
Time:        22.53 s
Force exiting Jest: Have you considered using `--detectOpenHandles`…
```

Los tests **pasan** en 22 s. Pero sólo terminan porque se añadió `--forceExit`.

`src/api/package.json` → `"test:e2e": "jest --config ./test/jest-e2e.json"`. Sin `--forceExit` y sin
`--runInBand`, que es exactamente como lo invoca CI.

## Los dos fallos, separados

| | |
|---|---|
| **La base llega sin esquema** | Los tests no pueden pasar aunque terminaran |
| **La suite no cierra sus manejadores** | Aunque el esquema estuviera, el job se queda colgado hasta el tiempo máximo del runner |

## Consecuencia en el grafo de jobs

```
lint ──┬── test-unit ───────┐
       └── test-integration ┴── build ── docker
```

`build: needs: [test-unit, test-integration]` (línea 160) y `docker: needs: build` (línea 191).
Con `test-integration` incapaz de terminar en verde, **`build` y `docker` nunca se ejecutan**.

## Lo que sí funciona

`security-audit` (línea 50) **no tiene `needs`**: es independiente y sí corre. El checkpoint D2 que
introdujo PT-118 no está afectado por esto. Se comprobó a mano y da 0 avisos (E-019).

## Lo que esta evidencia NO demuestra

No se consultó el historial de ejecuciones de GitHub Actions (`gh` no está disponible en este
entorno), así que no se sabe **desde cuándo** está así ni si alguien lo está mirando. Lo que se
demuestra es que, con el fichero tal y como está hoy, el job no puede terminar en verde.

## Limpieza

`ptsa_ci` y `ptsa_e2e` se eliminaron al cerrar la sesión.
