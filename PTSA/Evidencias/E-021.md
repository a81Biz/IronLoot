# E-021 — El camino de producción está roto en sus tres piezas

## 1. El healthcheck de la única imagen de producción apunta a un 404

`src/api/Dockerfile:60-61`

```dockerfile
HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
    CMD node -e "require('http').get('http://localhost:3000/health', \
        (r) => process.exit(r.statusCode === 200 ? 0 : 1))"
```

Contra el API en marcha:

```
  404  /health
  200  /api/v1/health
  404  /api/health
```

`src/api/src/main.ts:77` → `app.setGlobalPrefix('api')`, más versionado. La ruta real es
`/api/v1/health`.

El healthcheck del contenedor **de desarrollo** —el que define `docker-compose`— sí está bien:

```
["CMD","node","-e","require('http').get('http://localhost:3000/api/v1/health',
   (r) => process.exit(r.statusCode < 500 ? 0 : 1)).on('error', () => process.exit(1))"]
```

Se arregló ahí y no en la imagen de producción. Consecuencia: un contenedor de producción quedaría
`unhealthy` **de forma permanente** desde los 5 s de arranque, con la aplicación funcionando
perfectamente. Un orquestador lo reinicia en bucle o nunca le enruta tráfico.

Nótese también la diferencia de criterio: producción exige `statusCode === 200`; desarrollo acepta
`< 500` y captura el error de conexión. El de producción falla además si el health devuelve 503 por
degradación parcial, que es justo cuando conviene distinguir «degradado» de «muerto».

## 2. Tres de los cuatro servicios no tienen imagen de producción

```
./src/admin/Dockerfile.dev
./src/api/Dockerfile          ← la única de produccion
./src/api/Dockerfile.dev
./src/apps/base/Dockerfile.dev
./src/apps/client/Dockerfile.dev
./src/nginx/Dockerfile
```

ADMIN, BASE y CLIENT sólo tienen `Dockerfile.dev`, y `docker-compose` los construye con él. No
existe definición de imagen de producción para ninguno de los tres.

## 3. El job que construiría la imagen apunta a un fichero que no existe

`.github/workflows/ci.yml:201-207`

```yaml
      - name: Build Docker image
        uses: docker/build-push-action@v5
        with:
          context: .
          file: ./Dockerfile          ← no existe en la raiz del repositorio
          tags: ironloot-api:${{ github.sha }}
```

No hay ningún `Dockerfile` en la raíz. El job fallaría en el paso de construcción — si llegara a
ejecutarse, que no llega: `needs: build`, y `build` cuelga de `test-integration` (H-015).

## Lectura

Las tres piezas del camino a producción —esquema (H-014), pipeline (H-015) e imagen (esto)— están
rotas, y las tres por la misma causa: **nunca se han ejecutado.** No es un fallo; es un camino que
no se ha recorrido nunca y que nadie ha comprobado.

## Lo que esta evidencia NO demuestra

- No hay despliegue productivo afectado: no existe ninguno.
- No se construyó la imagen de producción para verificar que compila; sólo se leyó su definición y
  se comprobó en vivo la ruta a la que apunta su healthcheck.
