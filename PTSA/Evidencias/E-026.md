# E-026 — Los cinco checkpoints, ejecutados

`[A5]` — con acceso a shell, el auditor los ejecuta; no los pide.

## Los tres de CI: verdes

```
$ docker compose exec api npm run audit:schema
[audit:schema] OK — las migraciones reproducen `schema.prisma`.

$ docker compose exec api npm run audit:check
[audit:check] 0 paquete(s) con aviso propio en produccion.
[audit:check] OK — Sin novedades respecto a la linea base.

$ docker compose exec api npm run audit:observability
  silent_failure_count = 25   (linea base: 25)
  trace_completeness   = SIN CICLOS — no hay ciclos liquidados que evaluar
  OK — sin silencios nuevos.
```

`trace_completeness = SIN CICLOS` es el tercer estado que PT-138 introdujo. Dice que **no pudo
medir**, en vez de devolver `0 %` o `null`. Es la salida correcta con la base como está.

## Los dos de delta sync: fallan, y salen con código 0

```
$ docker compose exec api npm run audit:domain    ;  EXIT=0
/bin/sh: 1: docker: not found
  [n/d ] …19 reglas…
  rubric_compliance_score = null
  Todas las reglas quedaron SIN DATOS: no hay productos que evaluar.
  Esto NO es un 100: es una auditoria que no ha podido mirar.
  ...
  cross_coherence_verified = true          ← con las CINCO comprobaciones en (ERR)

$ docker compose exec api npm run audit:reliability ;  EXIT=0
/bin/sh: 1: docker: not found
  SIN_DATOS — no se pudo consultar la base
```

**Causa medida**, no inferida:

```
src/api/scripts/domain-rules.ts:268      execSync(`docker exec ${CONTENEDOR} psql …`)
src/api/scripts/reliability-check.ts:55  execSync(`docker exec ${CONTENEDOR} psql …`)
```

Dentro del contenedor del API no hay binario `docker`. Es **el mismo defecto** que PT-138 (F-135-B)
corrigió en `observability-check.ts` pasándolo a `PrismaClient.$queryRawUnsafe`: se arregló uno de
los tres y los otros dos se quedaron.

## Contraprueba: desde el host sí funcionan

```
$ cd src/api && npm run audit:domain              ;  EXIT=0
  [OK  ] CR-001 · CR-002 · CR-003 · CR-010 · CR-015 · R-5.1c · R-5.2b
  [n/d ] CR-004 · CR-005 · CR-006 · R-5.1a · R-5.1b · R-5.1d · R-5.3b
  rubric_compliance_score = 100
  Sin datos (fuera del denominador): 7 reglas

$ cd src/api && npm run audit:reliability          ;  EXIT=0
  Success / Retry / Failure  =  SIN_DATOS — no hay ciclos de pago que evaluar
  health_unstable = false
```

**Esto es lo que separa los dos hallazgos.** Que no corra en el contenedor (H-022) es un defecto de
sitio: se soluciona cambiando cómo consulta. Que imprima `cross_coherence_verified = true` con las
cinco comprobaciones en error (H-021) es otra cosa — **es afirmar sin haber medido**, y ocurre
independientemente de dónde se ejecute.

## Lo que esto significa para la cobertura de este delta sync

- **D1** se mide desde el host: **7 de 14 reglas**. Las otras 7 no tienen datos que mirar.
- **D5** no se mide: no hay un solo ciclo de pago en la base.

Se declara así en `RESUMEN.md` y baja `Confidence` por cobertura. `[A8]`: ningún score vale sin
cobertura declarada.
